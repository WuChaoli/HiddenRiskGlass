# 统一输入

关联总架构：[architecture.md](../architecture.md)

`UnifiedInputSession` 是当前正式主链的统一输入注册层。页面不再分别直接管理语音、触控、头部动作，而是声明动作和触发源。

## 核心约束

- 页面通过 `InputActionSpec` 声明业务动作
- `attach()` / `detach()` 跟随页面前后台
- `updateActions()` 跟随页面状态切换
- 当前正式主链默认只启用语音和触控
- 头部动作监听当前全局关闭，见 [统一输入设计与接入.md](C:\Users\wuchaoli\Desktop\codespace\glassdemo\docs\公共能力\统一输入设计与接入.md)
- 语音由当前前台 session 持有应用级词表所有权；新页面接管后，旧页面延迟 `detach()` 不得清空新词表
- 在 SDK `2.1.9-E` 基线上，词表优先以设备 `getLanguage()` 返回键调用 `setOfflineCmdWords(...)` / `clearOfflineCmdWords(...)` 整体切换；语言读取或覆盖失败时回退逐条 `add/remove`
- 当前不接入 `LeqiInterceptor`

## 通用语义

- Confirm：单击、语音“确认/确定/继续”
- Cancel：返回、双击、语音“返回/取消”
- 页面可以在不同状态下把 Confirm/Cancel 绑定到不同业务语义，但不应随意改变触发器集合

## 当前不再单列为业务模块的原因

- 输入层本身不承载独立业务旅程
- 它决定的是“同一页面在不同状态下如何触发业务动作”
- 因此统一输入现在作为公共能力维护，而不是单独拆成业务模块
