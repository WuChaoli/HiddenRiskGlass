# 功能模块文档模板

本文档用于把各功能目录统一收敛为“一个模块主文档 + 一个统一截图根目录”的结构。

推荐目录结构：

```text
docs/功能模块/
├── 功能模块.md
└── screenshots/
    └── 功能模块/
```

## 1. 功能目标

- 这个模块解决什么问题。
- 对用户、业务或巡检主链产生什么结果。

## 2. 功能边界

- 负责什么。
- 不负责什么。
- 依赖哪些前置模块、公共能力、配置或后端接口。

## 3. 用户旅程 / 主流程

按正式主链写 5-10 步，不在这里展开异常分支。

## 4. 页面与状态总览

建议用表格列出：

| 页面 | 状态 | 进入条件 | 退出条件 | 备注 |
| --- | --- | --- | --- | --- |
| `ExampleActivity` | `IDLE` | ... | ... | ... |

## 5. 页面详情

每个页面固定写：

- 页面职责
- 进入条件
- 退出路径
- 页面状态
- 关键 UI 元素
- 可见性约束
- 页面截图
- 截图说明

截图建议命名：

- `01_page_name_state.png`
- `02_page_name_state.png`

截图说明至少写清：

- 截图对应页面态
- 采集方式
- 是否为真机截图

## 6. 交互定义

按输入源拆开写：

- 触控指令
- 语音指令
- 头部动作

每条指令至少包含：

- 动作语义
- 指令文本
- 拼音
- 注册位置
- 生效页面态
- 触发结果

## 7. 页面跳转与路由规则

建议用表格列出：

| 来源页面 | 条件 / 动作 | 目标页面 | 失败 / 回退 |
| --- | --- | --- | --- |
| `PageA` | 初始化完成 | `PageB` | 返回 `PageA` |

## 8. 后端与数据链路

每条链路至少写清：

- 接口用途
- 触发时机
- 调用入口代码
- 请求来源数据
- 关键请求字段
- 关键响应字段
- 成功后的页面 / UI / 会话更新
- 失败后的降级、回退、提示
- 日志锚点

## 9. 会话与本地状态

建议按“谁持有、谁写入、谁消费”来写：

- `InspectionSession`
- `InspectionWorkflowSession`
- 页面内临时状态
- 配置项来源
- 页面间传递数据

## 10. 代码真相源

不要只列文件名，要按职责列：

- 页面真相源
- 输入真相源
- 接口真相源
- 会话真相源
- 配置真相源

每项尽量给到关键类和方法。

## 11. 异常与降级分支

至少覆盖：

- 初始化失败
- 网络失败
- 接口业务失败
- 会话未初始化
- 资源未就绪

每个分支要写清：

- 页面表现
- 用户可见提示
- 开发应检查的日志

## 12. 开发检查清单

建议用 Markdown task list：

- [ ] 代码实现检查
- [ ] 页面行为检查
- [ ] 指令注册检查
- [ ] 接口字段检查
- [ ] 会话写入检查
- [ ] 异常回退检查
- [ ] 真机验证检查

## 写法约束

- `docs/功能模块/` 下每个功能只保留一个正文真相源，不再拆 `功能说明`、`页面说明`、`页面跳转`、`用户旅程`、`代码索引`
- 公共能力只写一次，但模块文档必须写清“本模块如何使用”
- 所有后端描述都要落到代码入口，至少给到类名和方法名
- 所有语音指令都要按“文本 + 拼音 + 注册位置 + 生效页面态”记录
- 所有截图都要能对应到页面态
- 所有关键行为尽量写成“触发条件 -> 执行逻辑 -> 结果 -> 失败分支”
