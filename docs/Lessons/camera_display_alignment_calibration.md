# 摄像头画面与眼镜视野对齐：首轮实测参数与原因推理

> 记录日期：2026-08-18  
> 状态：首轮单人、单距离主观标定结果，可作为后续实验的基线；尚不是通用标定参数。

## 目标

在眼镜屏幕上以半透明方式显示摄像头画面，通过等比缩放和二维平移，使屏幕画面与右眼透过镜片看到的现实画面基本重叠。后续检测框、文字和标记复用同一变换后，可获得近似叠加在现实目标上的视觉效果。

理论初值与推导过程见 [`简化方案初始标定参数.md`](../assets/摄像头画面与眼镜画面对齐/简化方案初始标定参数.md)。

## 本轮测试条件

| 项目 | 数值或说明 |
|---|---|
| 摄像头理论输入 | 3024 × 4032 px，对角视场角 109° |
| 眼镜屏幕 | 480 × 640 px，对角视场角 30° |
| SDK 上报预览尺寸 | 4032 × 3024 px |
| 对齐计算采用的纹理坐标尺寸 | 3024 × 4032 px |
| Camera zoom level | 1 |
| 画面透明度 | 0.5 |
| 观察距离 | 约 1.5 m |
| 当时记录的主视眼 | 右眼；后续现场复核确认该组画面对齐实际以左眼为中心 |
| 右眼与摄像头间距 | 约 10～11 cm |
| 屏幕中心相对眼距中心的偏差 | 约 1 cm，方向尚未记录 |

SDK 的 `4032 × 3024` 上报值在当前链路中属于宽高轴交换；若直接用它计算纹理裁剪，会造成明显的横向拉伸。当前实现按请求的竖屏纹理语义 `3024 × 4032` 计算，因此画面方向和物体宽高比例正常。

## 首轮实测参数（后确认对应左眼）

从真机 `AlignmentCalibration result` 日志确认的最后一组参数为：

```text
scale   = 0.79049903
offsetX = 72.0 px
offsetY = -234.0 px
alpha   = 0.5
```

后续只调整 X 轴并交替用左右眼观察时确认：上述 `offsetX = +72` 对应左眼中心，而不是最初记录的右眼中心。原因推理中涉及水平偏移的角度和距离量级仍可作为绝对值参考，但左右方向归属以最终双眼预设为准。

对应日志中的归一化纹理裁剪区域：

```text
crop = [0.36948168, 0.47301780, 0.20079742, 0.20079742]
```

这里的裁剪数组含义为 `[left, top, width, height]`。换算到 `3024 × 4032` 纹理后，裁剪窗口约为 `607.21 × 809.62 px`，中心约为 `(1420.92, 2312.02)`。

当前坐标变换可记录为：

```text
screenX = 240 + (cameraX - 1512) × 0.79049903 + 72
screenY = 320 + (cameraY - 2016) × 0.79049903 - 234
```

按当前纹理矩阵的实现语义：

- `offsetX = +72` 表示画面向屏幕右侧移动，对应纹理采样中心向左移动约 `91.08 px`；
- `offsetY = -234` 表示画面向屏幕上方移动，对应纹理采样中心向下移动约 `296.02 px`。

## 与理论值的差异

理论等比缩放为 `0.830499`，实测为 `0.79049903`：

```text
实测值 / 理论值 ≈ 0.95184
```

即实测缩放比理论值低约 `4.82%`，对应的相机裁剪窗口比理论窗口大约 `5.06%`。若仅把差异归因于视场角：

- 保持相机对角视场角 `109°` 不变，屏幕的等效对角视场角约为 `31.44°`；
- 保持屏幕对角视场角 `30°` 不变，相机的等效对角视场角约为 `106.31°`。

这两个结果只能作为“有效视场角与标称值存在差异”的等价解释，不能据此判定是哪一个标称参数不准确。

## 可能原因推理

### 1. 水平偏移主要可能来自眼睛与摄像头的视差

右眼与摄像头相距约 `10～11 cm`，目标距离约 `1.5 m`，只考虑水平基线时，对应视差角约为：

```text
atan(0.10 / 1.5) ～ atan(0.11 / 1.5)
≈ 3.81° ～ 4.19°
```

当前水平偏移反推的等效角度约为 `2.90°`，相当于 1.5 m 距离下约 `7.6 cm` 的有效横向基线。它与 10～11 cm 的物理间距处于同一量级，但并不完全相等。可能还叠加了以下因素：

- 屏幕光学中心相对右眼的位置，而不是相对双眼中心的位置；
- 已知约 1 cm 的屏幕中心偏差；
- 摄像头主点并非传感器几何中心；
- 相机和显示光轴不完全平行；
- 目标距离约值、视场角标称值和人工对齐误差。

由于尚未记录摄像头位于右眼的哪一侧，以及屏幕中心偏差的具体方向，目前只能判断量级合理，不能唯一分解每一项贡献。

### 2. 垂直偏移不能仅用已知物理间距解释

`offsetY = -234 px` 反推的等效角度约为 `9.35°`。若完全解释为 1.5 m 处的眼睛—摄像头垂直视差，需要约 `24.7 cm` 的垂直基线，这显然远大于正常眼镜结构尺寸。

因此，垂直偏移更可能主要来自：

- 显示光学中心与屏幕像素中心不一致；
- 摄像头光轴与佩戴者视线存在俯仰角；
- 摄像头主点偏移；
- 预览链路仍存在固定的垂直裁剪或坐标原点差异；
- 眼镜佩戴姿态和人工选取的对齐目标。

### 3. 缩放差异主要属于有效视场角问题

平移视差会随目标距离明显变化，而本轮约 `4.82%` 的缩放差异更符合有效 FOV、显示光学放大率、相机内参或预览裁剪造成的固定比例差异。仅凭一个距离上的主观标定，暂时不能区分这些来源。

## 适用边界与下一步验证

当前参数针对一名佩戴者、右眼观察和约 1.5 m 目标得到。由于摄像头与眼睛不共点，同一组平移参数不可能让所有深度的目标同时严格重合。

建议在保持佩戴姿态不变的条件下，分别对约 `0.5 m、1.5 m、3 m` 的目标记录最终参数：

- 若缩放基本不变，可将 `scale = 0.79049903` 视为当前设备的固定有效视场角参数；
- 若平移随距离呈近似反比变化，可确认变化部分主要来自眼睛—摄像头视差；
- 若某部分平移在不同距离下基本不变，可将其归入光轴、主点或显示光学中心的固定偏差；
- 后续还应记录摄像头相对右眼的水平/垂直方向、屏幕中心偏差方向和设备佩戴姿态，以建立可计算的深度相关模型。

## 在线 bbox 与 label 演示

标定测试页现已增加隔离的在线识别演示，不接入成熟业务页面。页面通过 `PixelCopy` 截取已经应用本页缩放和平移参数的 Surface 画面，中心裁剪为严格 3:4，再放大为默认 `960 × 1280` 的 JPEG 请求图像。由于请求图像和屏幕显示的是同一已标定视野，服务端 bbox 按左上角原点等比映射回 `480 × 640` 即可，不再重复应用相机标定矩阵。

当前测试页将相机 Surface 的显示透明度固定为 `0`，眼镜屏幕只显示 bbox 和 label；Surface 会话及后台截帧仍继续运行。需要重新校准时使用独立的半透明距离标定页，不在打框页内切换透明度。

### 距离相关水平偏移公式

2026-08-19 基于右眼佩戴状态下 1–4 m 的人工重叠校准结果，以倒数关系拟合并做 1 m 微调后，打框测试页采用以下参数。经真机多距离测试，现实目标与渲染框的整体偏移处于可接受范围，因此将其记录为当前验证基线：

```text
offsetX(distance) = B - K / distance
B = 108.00 px
K = 115.94 px·m
distance 单位 = m
```

验证状态与适用条件：

- 状态：真机测试确认，可作为当前打框测试页的默认参数；
- 观察眼：右眼；
- 设备与佩戴：当前 Rokid Glass 设备及本轮佩戴姿态；
- 距离范围：已重点验证约 `1–4 m`，`0.5 m` 参数为公式外推值；
- 固定项：`scale = 0.79049903`、`offsetY = -234 px`、`alpha = 0`；
- 调节方式：距离以 `0.5 m` 为步长，变化后实时重算 `offsetX`。

固定参数为 `scale = 0.79049903`、`offsetY = -234 px`、`alpha = 0`。减小 `B` 会让所有距离下的渲染画面等量左移；当前公式的参考值如下：

| 距离 | offsetX |
|---:|---:|
| 0.5 m | -123.88 px |
| 1.0 m | -7.94 px |
| 1.5 m | 30.71 px |
| 2.0 m | 50.03 px |
| 3.0 m | 69.35 px |
| 4.0 m | 79.02 px |

打框测试页初始距离为 `1.0 m`。前滑将距离减小 `0.5 m`，后滑将距离增大 `0.5 m`，最小距离为 `0.5 m`；每次变化都会立即按上述公式重算水平偏移。单击不再切换标定轴，双击或返回键退出页面。

## 历史左右眼固定距离预设

两套参数使用相同的缩放、Y 轴偏移和水平偏移绝对值，仅 X 轴方向相反：

| 主用眼 | scale | offsetX | offsetY | 默认 alpha |
|---|---:|---:|---:|---:|
| 左眼 | 0.79049903 | +72 | -234 | 0 |
| 右眼（默认） | 0.79049903 | -72 | -234 | 0 |

ADB 切换方式：

```powershell
# 默认右眼；dominantEye 可省略
adb shell am start -n `
  com.rokid.glesse/com.rokid.glass.hiddenrisk.RawCameraPreviewDebugActivity `
  --es mode alignment_calibration `
  --es dominantEye right

# 左眼
adb shell am start -n `
  com.rokid.glesse/com.rokid.glass.hiddenrisk.RawCameraPreviewDebugActivity `
  --es mode alignment_calibration `
  --es dominantEye left
```

上述固定偏移预设保留为早期人工标定记录。当前 `alignment_calibration` 打框测试模式已改用距离相关公式，不再读取 `scale`、`offsetX`、`offsetY` 的 ADB 覆盖值；需要继续手工拟合 B/K 时使用独立的 `InverseDistanceAlignmentTestActivity`。
