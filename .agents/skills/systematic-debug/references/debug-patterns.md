# 调试模式速查表

## 按场景分类

### 崩溃/Crash

| 模式 | 策略 | 工具/命令 |
|------|------|----------|
| 堆栈回溯 | 从最底层 frame 向上追踪，关注 own code | `bt full` (gdb), crash log |
| 空指针/NPE | 在赋值路径上加 null guard 日志，定位首个 null | 条件断点: `value == null` |
| 段错误 | 用 AddressSanitizer / Valgrind 定位非法内存访问 | `-fsanitize=address` |
| 栈溢出 | 检查递归终止条件、大局部变量 | `ulimit -s`, 堆栈大小监控 |

### 逻辑错误

| 模式 | 策略 | 工具/命令 |
|------|------|----------|
| 数据流追踪 | 标记关键变量的每次变更，追踪污染源 | printf/subagent 注入日志 |
| 控制流验证 | 在每个分支打印决策条件，验证走了预期的分支 | log + grep |
| 不变量检查 | 在每个函数入口/出口 assert 不变量 | `assert`, `require` |
| 参照实现对比 | 找到类似功能但正常工作的代码，对比差异 | `diff` between modules |

### 性能问题

| 模式 | 策略 | 工具/命令 |
|------|------|----------|
| 热点分析 | profiler 定位 CPU 占比最高的函数 | `perf`, `pprof`, `flamegraph` |
| N+1 查询 | 在 ORM 层打点，统计同类查询次数 | query counter |
| 内存泄漏 | 随时间取样 heap，找持续增长的对象 | heap dump 对比 |
| 锁争用 | 分析锁等待时间分布 | lock profiling, `jstack` |

### 并发问题

| 模式 | 策略 | 工具/命令 |
|------|------|----------|
| 死锁 | 捕获线程栈，分析锁的持有-等待图 | `jstack`, `thread apply all bt` |
| 竞态条件 | ThreadSanitizer 检测 data race | `-fsanitize=thread` |
| 顺序依赖 | 打印事件顺序，对比预期时序 | 带时间戳的 event log |
| 活锁 | 观察 CPU 高但无进展，检查重试循环 | 对重试计数加日志 |

### 网络/IO

| 模式 | 策略 | 工具/命令 |
|------|------|----------|
| 超时排查 | 在调用链每个节点记录耗时，定位瓶颈 | 分布式 trace |
| 连接泄漏 | 定期打印连接池状态，观察增长趋势 | connection pool metrics |
| 数据损坏 | 校验和对账，定位传输环节 | checksum comparison |
| 协议错误 | 抓包对比工作/不工作的交互序列 | `tcpdump`, Wireshark |

### 环境/配置

| 模式 | 策略 | 工具/命令 |
|------|------|----------|
| 环境不一致 | 导出两环境完整 env/配置，逐项 diff | `env`, `diff` |
| 依赖冲突 | 打印实际加载的依赖版本树 | `npm ls`, `pip freeze`, `mvn dependency:tree` |
| 资源耗尽 | 检查 ulimit、磁盘、inotify 等系统限制 | `ulimit -a`, `df -h` |
| 权限问题 | 确认运行用户、文件权限、SELinux | `ls -l`, `id`, `getenforce` |

## 调试反模式

| 反模式 | 为什么坏 | 正确做法 |
|--------|---------|---------|
| 随机魔改代码试错 | 可能引入新 bug，无法验证 | 每次只改一个变量 |
| 不加日志就推测 | 凭空猜测浪费时间 | 先加日志再分析 |
| 跳过复现直接分析 | 无法验证结论 | 复现优先 |
| 同时改多处 | 不知道哪个改对了 | 逐一隔离 |
| 回滚后不复现就宣布"修好了" | 不知道根因，下次还来 | 追到根因为止 |
| 修复后不写测试 | 下次重构可能回归 | 每个 bug 必须带测试 |
